## 목표

아래 중 **하나**를 골라 구현합니다. 무엇을 고르든 **NEED 규칙**과 SPEC → 구현 → 검증 순서는 같습니다.

| 과제 | 개념 | 손댈 곳 |
|---|---|---|
| **A. Undo (Z)** — 예시 정답 있음 | 상태 기록 스택 | `Game/SokobanGame` |
| B. 부드러운 이동 | 보간, 표시 위치와 논리 위치의 분리 | `Game/GridView`, `Game/main.cpp` |
| C. 텍스처 | UV, 샘플러, `WICTextureLoader` | `Render/` (+ 정점 형식) |
| D. 레벨 추가 + 레벨 검증 | 레벨 설계, 00단계 시나리오 테스트 확장 | `Game/levels/`, 00단계 테스트 |

starter에는 A의 `TODO(12)`가 들어 있습니다. B~D를 고르면 starter를 11단계 정답처럼 쓰고, 고친 파일과 이유를 SPEC에 적습니다.

## A. Undo

- 성공한 이동 **직전** 상태를 `history_`에 넣고, Z를 누르면 마지막 것으로 돌아갑니다.
- 상태가 값(`Level`)이라 통째로 저장하면 됩니다. 08단계부터 지켜 온 "상태가 진실"의 보상입니다.
- 막힌 이동은 기록하지 않습니다. Clear 뒤에 Undo하면 다시 `Playing`입니다.

## B~D 힌트

- **B:** 논리 위치(`level_.player`)는 즉시 바뀝니다. 화면용 위치만 따로 두고 매 프레임 논리 위치로 다가가게 합니다. 규칙 코드는 건드리지 않습니다.
- **C:** 텍스처는 Render 안에서만 다룹니다. Game은 "이 메시를 이 색으로"처럼 "이 메시를 이 재질로"만 말해야 합니다. 레이어 검사를 통과해야 합니다.
- **D:** 새 레벨마다 00단계 방식의 시나리오(풀이 입력 → Clear)를 테스트에 추가합니다.
