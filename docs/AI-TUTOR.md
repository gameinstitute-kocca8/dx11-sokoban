# AI 튜터 사용 규칙

AI는 **코드 생성기가 아니라 튜터**입니다. 요구사항을 검토하고, 원인 후보를 좁히고, 개념을 설명하는 데 씁니다.

AI 사용 자체는 감점 대상이 아닙니다. 평가는 AI가 낸 제안을 **이해하고, 제한하고, 고치고, 검증할 수 있는지**를 봅니다 ([ASSESSMENT.md](ASSESSMENT.md)의 "AI 활용" 루브릭).

## 어떤 도구를 써도 된다

ChatGPT, Gemini, Claude, Copilot 등 무엇이든, 무료 버전이어도 됩니다. 평가는 도구의 성능이 아니라 **내가 질문을 좁히고 답을 검증한 과정**을 봅니다.

다만 웹 채팅은 이 레포의 규칙 파일(`AGENTS.md`, `CLAUDE.md`)을 읽지 못합니다. 그래서 단계별 `AI-TUTOR.md` 맨 위의 **시작 프롬프트**를 새 대화마다 첫 메시지로 붙여 넣습니다. 시작 프롬프트가 아직 없는 단계는 13단계의 것을 단계 이름과 "꺼내지 말 개념"만 바꿔 씁니다.

## 묻기 전에

`templates/QUESTION.md`를 채웁니다.

```text
현재 단계:
기대 화면/결과:
실제 화면/결과:
확인한 로그 (출력 창의 [실패], 디버그 레이어, RenderDoc):
이미 시도한 것:
내 가설:
관련 코드 (함수 하나):
AI에게 바라는 도움:
답을 받으면 내가 실행할 검증:
```

**한 질문에는 함수 하나와 확인 조건 하나만** 담습니다. "엔진 구조를 만들어 줘", "소코반 전체를 짜 줘" 같은 요청은 하지 않습니다.

## AI에게 요구하는 행동

이 규칙은 레포의 `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`에도 들어 있어서, 해당 도구들이 자동으로 읽습니다.

1. 요구사항의 빈칸과 모순을 먼저 지적한다.
2. 현재 단계 밖의 기술을 제안하지 않는다. 단계별 `AI-TUTOR.md`의 범위를 따른다.
3. 전체 파일, 새 클래스 구조, 새 프레임워크를 생성하지 않는다.
4. 원인 후보는 최대 두 개만 제시한다.
5. 코드보다 먼저 로그, 디버그 표시, 최소 실험을 제안한다.
6. 코드가 필요하면 기존 함수 안의 작은 수정만 제시한다.
7. 학생에게 변경 이유와 검증 방법을 자기 말로 설명하게 한다.
8. 리플렉션, 에디터, ECS, 물리 엔진, 렌더러 교체 추상화를 제안하지 않는다.

## 학습 기록 (`LOG.md`)

단계마다 1~2건만 적습니다. 데모 때 이 중 하나를 골라 질문합니다. 양식은 `templates/LOG.md`입니다.

- **원문을 남깁니다.** 내가 보낸 질문 한두 줄과 AI 답의 핵심 몇 줄을 요약하지 말고 옮깁니다.
- **거절하거나 고쳐 쓴 경우가 단계마다 1건 이상** 있어야 합니다. AI 말을 그대로 따른 기록만으로는 판단력을 보여 줄 수 없습니다.
- **검증 결과**는 화면, 로그, 테스트 출력처럼 다른 사람이 다시 확인할 수 있는 것으로 적습니다.
